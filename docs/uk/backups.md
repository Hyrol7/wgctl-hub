# Резервні копії

wgctl зберігає зашифровану копію всього, що потрібно, щоб відновити хаб: налаштування й ключі (`/etc/wgctl`, `/etc/wireguard`, `/etc/caddy`, `/etc/vpnadmin`), брандмауер, служби systemd, самі програми, дані Signal і базу історії.

Копії шифруються [age](https://age-encryption.org) на публічний ключ. **Секретний ключ показується один раз і ніколи не зберігається на сервері**, тож викрадений сервер чи файл копії нічого не розкриють.

## Налаштування

```bash
sudo wgctl backup init
```

- показує `AGE-SECRET-KEY-…` — одразу збережіть його в менеджері паролів;
- записує публічний ключ у `/etc/wgctl/backup-recipient.txt`;
- вмикає `wgctl-backup.timer` (щодня о 03:40 за часовим поясом хаба).

## Що відбувається щодня

- створюється файл `/var/backups/wgctl/wgctl-РРРРММДД-ГГХХ.tar.gz.age`; зберігаються останні 14;
- якщо налаштовано Signal, файл надсилається адмінам, коли конфігурація змінилась, і щонайменше раз на тиждень;
- якщо копії не було понад 36 годин, про це скаже сторінка «Сервер» і сповіщення.

```bash
sudo wgctl backup run         # зараз
sudo wgctl backup status
sudo wgctl backup verify      # вставте секретний ключ: перевіряє, що він справді розшифровує останню копію
```

## Відновлення

На тому самому або новому сервері (спершу встановіть wgctl через `./install.sh`, `wgctl init` можна пропустити):

```bash
sudo wgctl backup restore wgctl-20261029-0340.tar.gz.age            # перегляд: список файлів, нічого не змінює
sudo wgctl backup restore wgctl-20261029-0340.tar.gz.age --apply    # записує файли; попросить написати «так»
sudo wgctl render
sudo systemctl restart wg-quick@wg0 caddy vpnadmin
```

Поточні файли спершу зберігаються. Якщо новий сервер має іншу публічну IP, оновіть `public_ip`/`endpoint_host` у `/etc/wgctl/config.toml` — а краще з самого початку вкажіть DNS-ім'я в `endpoint_host`, тоді клієнтам ніколи не знадобляться нові конфіги.

Відновлення питає секретний ключ інтерактивно; запускайте його в SSH-терміналі.
