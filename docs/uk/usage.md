# Щоденне користування

Усе можна робити в панелі (`https://vpnadmin.<домен>`, лише для адмін-ключів) або командою `sudo wgctl …` через SSH. Панель викликає ті самі команди.

## Ключі

Ключ — це один конфіг WireGuard для одного пристрою. Імена: малі латинські літери, цифри й дефіс, до 31 символу (`iphone-olena`, `work-laptop`).

```bash
sudo wgctl add iphone-olena --sites nas,photos --phone +380671234567 --qr
sudo wgctl add work-laptop --sites '*'            # усі сайти, включно з майбутніми
sudo wgctl add anna --hours 4 --sites photos     # гостьовий ключ, відкличеться сам за 4 год
sudo wgctl list                                  # --all показує і відкликані
sudo wgctl show iphone-olena
```

| Команда | Що робить |
|---|---|
| `wgctl conf ІМ'Я` / `wgctl qr ІМ'Я` | ще раз показати збережений конфіг / QR |
| `wgctl grant ІМ'Я сайт…` / `wgctl deny ІМ'Я сайт…` | додати чи забрати сайти |
| `wgctl set ІМ'Я --sites nas,photos` | замінити список сайтів (`*` = усі, `none`) |
| `wgctl set ІМ'Я --expires 2026-12-31` | термін дії; після нього ключ вимикається |
| `wgctl extend ІМ'Я` | почати 60-денний відлік неактивності заново; гостю — `--hours 2` |
| `wgctl disable ІМ'Я` / `enable` | тимчасово вимкнути; пристрій бачить сторінку «Доступ вимкнено» |
| `wgctl reissue ІМ'Я` | нові ключі; старий конфіг перестає працювати (зміна ключа) |
| `wgctl revoke ІМ'Я` | відкликати назавжди |
| `wgctl set ІМ'Я --admin on` | ключ може відкривати панель (лише постійні ключі) |

**Автовідкликання.** Ключ, який не підключався 60 днів (`policy.inactive_days`), відкликається; користувач і адміни отримують попередження за 7 днів. Вимкнути для ключа: `--no-autorevoke` або `--autorevoke off`.

**Зміна ключів.** Через `rotate_days` (типово 180) панель позначає ключ «час змінити ключ» і надсилає нагадування. Змінити період: `sudo wgctl config --rotate-days 90` (0 = вимкнено).

## Сайти

```bash
sudo wgctl site add nas http://192.168.1.10:5000
sudo wgctl site add pve https://192.168.1.11:8006 --insecure        # самопідписаний сертифікат бекенда
sudo wgctl site add ha http://192.168.1.12:8123 --upstream-host     # бекенд чекає власний Host
sudo wgctl site list
sudo wgctl site set nas --backend http://192.168.1.10:5001
sudo wgctl site rm nas
```

Сайт доступний як `https://nas.<домен>`. Бекенд завжди задається IPv4-адресою (без імен хостів, щоб DNS не перенаправив сайт деінде): у мережі однієї з локацій, на пристрої з ключем або на самому VPS (`http://127.0.0.1:3000`). На VPS дозволені лише порти від 1024, крім API Caddy (2019), панелі (8090) і портів TCP-сервісів (2201–2999).

Ключ без доступу до сайту бачить сторінку «немає доступу»; якщо бекенд не відповідає — «Сайт тимчасово недоступний».

### Публічні сайти

Сайт можна також опублікувати в інтернет через Cloudflare (у режимі проксі: адреса VPS прихована за Cloudflare, і до порту 443 може дістатися лише Cloudflare):

```bash
sudo wgctl cloudflare --zone <Zone ID>
sudo wgctl site set blog --public on        # створює проксований запис DNS ім'я.<домен> -> VPS
sudo wgctl site set blog --public off       # прибирає його; знову лише через VPN
```

Щоб секрети з адреси (шлях webhook, токени в параметрах) не потрапляли в `/var/log/caddy/wgctl-access.log` (і для сайтів лише через VPN, і для публічних): `sudo wgctl site set blog --log hide-path` пише в журнал лише перший сегмент шляху (`/hook/[hidden]`), `--log off` не пише сайт у журнал зовсім. `--log-skip /s,/health` не пише лише ці шляхи (шаблони шляхів Caddy, працює й `/static/*`; `none` очищає). Заголовки `Authorization` і `Cookie` у журнал не потрапляють ніколи.

Публічний сайт може відкрити будь-хто в інтернеті, тож публікуйте лише те, що має бути публічним і захищене власним входом.

## Моніторинг і сигнали безпеки

`wgctl-monitor.timer` щохвилини запускає `wgctl monitor`. Він записує підключення й трафік, перевіряє сайти й сервіси і створює події:

- ключ підключився з **нової країни** чи від хостинг/VPN-провайдера, через **Tor**, або з **неможливою швидкістю подорожі** між двома місцями — ключ позначається *під підозрою*;
- **подвійна активність** (той самий ключ перескакує між адресами — ймовірно, конфіг скопійовано);
- локація без зв'язку понад 10 хвилин, бекенд чи TCP-сервіс перестав відповідати;
- попередження про термін дії, автовідкликання і кінець гостьового часу; сертифікат; диск, оновлення, копії.

`wgctl trust ІМ'Я` («це я») довіряє поточній країні/провайдеру і знімає позначку; `wgctl disable ІМ'Я --reason suspicious` блокує ключ.

## Журнал, відвідування і графіки

```bash
sudo wgctl log -n 50 --cat security
sudo wgctl visits --days 7               # запити за сайтами й ключами, підсумки за дні (з журналу Caddy)
sudo wgctl history on:iphone-olena,up:nas --range 7d
sudo wgctl server                        # диск, пам'ять, оновлення, служби, сертифікат, копії
sudo wgctl status
```

Панель показує те саме з графіками на сторінках ключа, сайту, локації і сервера. Історія зберігається 90 днів.
