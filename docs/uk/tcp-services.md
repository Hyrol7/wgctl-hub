# TCP-сервіси: SSH, RDP, VNC та інші

Не все є вебсайтом. **TCP-сервіс** зв'язує порт на хабі з адресою:портом за локацією — лише для вибраних ключів:

```
ноутбук ──► 10.77.0.1:2201 ──(systemd-socket-proxyd)──► 192.168.1.20:22
```

## Разове налаштування

```bash
sudo wgctl tcp setup
```

Встановлює два шаблони служб systemd (`wgctl-tcp@.socket`, `wgctl-tcp@.service`) і перевіряє, що `/etc/nftables.conf` переходить у ланцюг `wgctl_tcp` (брандмауер від інсталятора це вже має). Запускайте в SSH-терміналі: команда покаже зміни й попросить підтвердження.

Проксі працює від тимчасового `DynamicUser` у суворій пісочниці, слухає лише VPN-адресу хаба і доступний лише з дозволених ключів (окреме правило nftables для кожного сервісу).

## Додавання сервісу

```bash
sudo wgctl tcp add nas-ssh 192.168.1.20:22          # отримає перший вільний порт хаба з 2201
sudo wgctl tcp add laptop-rdp 192.168.1.30:3389 --port 2389
sudo wgctl tcp allow nas-ssh work-laptop
sudo wgctl tcp list
```

Потім із дозволеного пристрою з увімкненим тунелем:

```bash
ssh -p 2201 user@nas-ssh.example.org        # ім'я вказує на 10.77.0.1, як і будь-який сайт
```

Для RDP підключайтесь до `laptop-rdp.example.org:2389`.

Інші команди: `wgctl tcp set ІМ'Я --target 192.168.1.21:22`, `wgctl tcp deny ІМ'Я КЛЮЧ…`, `wgctl tcp rm ІМ'Я`. Вимкнений чи відкликаний ключ одразу втрачає доступ.

## Роутер

Брандмауер локації має дозволяти хабу доступ до порту цілі (додайте `22`, `3389`, `5900`… у правило forward із [локацій](locations.md)). Ціль бачить підключення з `10.77.0.1` (або з LAN-адреси роутера, якщо ввімкнено srcnat) — дозвольте це у власному брандмауері пристрою, напр. у правилі «Віддалений робочий стіл» Windows.

## Обмеження

- Порти хаба 2201–2999; ціль має бути в мережі локації або на пристрої з ключем.
- Власні порти хаба (SSH, 80, 443, адмінка Caddy, панель) ніколи не можуть бути ціллю.
- До 32 одночасних підключень на сервіс.
